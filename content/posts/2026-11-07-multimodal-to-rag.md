## 07 · 多模态大模型

- **定义**：能同时理解和生成多种模态（文本、图像、音频、视频）的大模型。
- **代表**：GPT-4o / GPT-4V、Gemini、Qwen-VL、Claude 3、GPT-4o。
- **核心思路**：把不同模态的数据都映射到同一个语义向量空间，让文本和图像在模型眼里"说同一种语言"。
- **典型能力**：看图说话、图文问答、视频理解、语音对话、文档扫描件直接读。
- **和纯文本 LLM 的区别**：输入不再只是文字，而是"文字 + 像素 + 波形"的混合体。

## 08 · AIGC

- **定义**：AI Generated Content，人工智能生成内容。
- **内容形式**：
  - 文本：写作、摘要、翻译、代码
  - 图像：Midjourney、Stable Diffusion、DALL·E
  - 音频：TTS 语音合成、AI 唱歌、音效生成
  - 视频：Sora、可灵、Runway
  - 3D / 数字人 / 虚拟场景
- **和传统内容生产的区别**：
  - PGC（专业生产）：人写、人拍，质量高但慢
  - UGC（用户生产）：普通人上传，量大但杂
  - AIGC：一句话生成，成本极低、速度极快
- **本质**：大模型从"理解语言"走向"创造内容"。

## 09 · AIGC 实战：AI 短视频制作

一条 AI 短视频的典型流水线：

1. **脚本生成**：用 LLM 写分镜脚本、旁白文案。
2. **AI 配音**：TTS 把文案转成语音，可选音色、情绪、语速。
3. **画面生成**：用文生图 / 文生视频工具按分镜生成画面。
4. **剪辑合成**：把画面、配音、字幕、背景音乐拼到一起。
5. **字幕与封面**：自动生成字幕，AI 做封面图。

> 核心变化：以前一个团队干一周的活，现在一个人一下午就能出片。

## 10 · Prompt 提示词

- **定义**：你给大模型的输入指令，决定了它输出什么。
- **好 Prompt 的结构**：
  - **角色**：你是一个资深文案 / 律师 / 老师
  - **任务**：写一篇 300 字的产品介绍
  - **要求**：语气活泼、面向大学生、带 emoji
  - **示例**：给 1-3 个 few-shot 样例
  - **输出格式**：JSON / Markdown / 表格
- **常用技巧**：
  - Zero-shot：直接下指令
  - Few-shot：给几个例子再让它做
  - CoT（思维链）：加一句"请一步一步思考"
  - 角色设定 + 约束条件
- **一句话**：Prompt 写得好不好，直接决定了同一个模型输出质量的上限。

## 11 · Token 词元

- **定义**：大模型处理文本的最小单位，**不是字，也不是词，而是"子词"**。
- **为什么不用字/词**：
  - 按字：序列太长，计算量爆炸
  - 按词：词表太大，生僻词没法处理
  - 按子词（BPE）：平衡词表大小和序列长度
- **换算感受**：
  - 中文：1 个汉字 ≈ 1~2 个 token
  - 英文：1 个常见单词 ≈ 1 个 token
  - 标点、空格也算 token
- **为什么要关心**：模型按 token 计费、按 token 算上下文长度、按 token 算生成速度。

## 12 · Token 的流转过程

一句话把文本变成模型能吃的东西：

```
原始文本 "你好世界"
  → 分词器 Tokenizer 切分 → ["你", "好", "世界"]
  → 查词表 → token id [1234, 5678, 9012]
  → Embedding 层 → 每个 id 变成一个 向量（比如 4096 维）
  → 加位置编码 → 告诉模型谁在前谁在后
  → 送进 Transformer 层
```

> 你输入的每个字，在模型眼里都是一串数字向量。

## 13 · Token 进入大模型后发生了什么

1. **Embedding + 位置编码**：token id → 向量，加上位置信息。
2. **多层自注意力 Self-Attention**：每个 token 和其他所有 token 算关联权重，理解上下文。
3. **前馈网络 FFN**：逐位置做非线性变换。
4. **残差连接 + LayerNorm**：让几十上百层的网络还能训得动。
5. **输出投影**：最后一个位置的隐状态 → 词表大小的 logits → Softmax → 下一个 token 的概率分布。
6. **采样**：按 Temperature / Top-p 选出下一个 token，拼回去继续循环。

> 模型本质上就是一个超大的"下一个 token 预测机"。

## 14 · Context Window 上下文窗口

- **定义**：模型一次能"看到"的最大 token 数（输入 + 输出总和）。
- **典型大小**：
  - 早期模型：4K、8K
  - 现在主流：128K、200K
  - 长上下文模型：1M 甚至更多
- **为什么重要**：
  - 超出窗口的内容会被"遗忘"（截断）
  - 对话越长，越前面的内容越容易被忽略
  - 窗口越大，能一次塞进去的资料越多，但成本也越高
- **和记忆的关系**：上下文窗口 = 模型的"短期记忆"。

## 15 · 记忆 Memory

- **真相**：大模型本身**没有记忆**。
- **所谓"记忆"是怎么来的**：
  - **短期记忆**：把历史对话全部放在 Context Window 里，每次都带着一起输入。
  - **长期记忆**：模型本身存不住，需要外挂——
    - 把历史对话存数据库，下次检索相关片段塞回上下文
    - 用 RAG 把外部知识库接进来
- **类比**：模型像一个每次都失忆的天才，你每次跟它说话都得把前情提要重新念一遍。

## 16 · RAG 检索增强生成

- **全称**：Retrieval-Augmented Generation，检索增强生成。
- **解决什么问题**：
  - 模型幻觉（一本正经地编）
  - 知识过时（训练数据有截止日期）
  - 私有数据（公司内部资料没进训练集）
- **工作流程**：
  1. 用户提问
  2. 先去外部知识库（向量数据库）检索相关文档片段
  3. 把检索到的片段 + 用户问题一起塞进 Prompt
  4. 让模型**基于这些资料**回答，而不是凭空编
- **一句话**：RAG = 开卷考试。模型不用背下所有知识，考试时翻书就行。

## 今日小结

从 07 到 16，其实是一条完整的线：

- **多模态**让模型不只懂文字，还能看图听声；
- **AIGC** 让模型从"理解"走向"创造"；
- **Prompt** 是人怎么指挥模型；
- **Token** 是模型眼里文字的最小单位；
- **上下文窗口** 是模型一次能看多少东西；
- **记忆** 是模型怎么"记住"你说过的话；
- **RAG** 是给模型外挂一个知识库，让它开卷考试、减少幻觉。

理解了 Token → 上下文 → 记忆 → RAG 这条链，就理解了为什么大模型"看起来很聪明但有时候会胡说八道"，以及工程上怎么把它变得更靠谱。
