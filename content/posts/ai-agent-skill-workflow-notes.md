今天刷了课程的 21~24 节，主题是 AI Agent 的两个核心概念：**Skill（技能）** 和 **Workflow（工作流）**。记一下理解。

## 一、Skill 技能

### 是什么

Skill 可以理解成给 AI 装上的"一项本事"。AI 本身只会聊天，给它加一个 Skill，它就多了一项能力——比如查天气、读网页、写代码、调用某个 API。

打个比方：
- AI 本体 = 一个聪明但什么工具都没有的人
- Skill = 给他一把锤子、一个卷尺、一本手册

AI 不需要"学会"怎么用锤子，只要你告诉它"什么时候该用锤子"，它就自己会调用。

### 核心特点

- **可复用**：一个 Skill 写好，可以被多个 Agent 反复调用
- **解耦**：Skill 内部怎么实现的，Agent 不需要关心，只需要知道"这个 Skill 能干嘛、需要什么参数"
- **按需调用**：不是每句话都用所有 Skill，AI 会根据用户问题自己判断该不该用

### 实操：用 Skill 做一个网站

这一节是动手环节，用 Skill 让 AI 自动生成了一个网站。关键点不是"AI 写代码"这件事本身，而是体会：

1. **Skill 的描述（description）很重要**——AI 是看描述来决定什么时候调用这个 Skill 的，描述写得不准，它就会乱调或者不调
2. **输入输出要定义清楚**：Skill 需要什么参数、返回什么格式，都要提前约定好
3. **调试方式**：先单独测 Skill 能不能跑通，再接到 Agent 里

## 二、Workflow 工作流

### 是什么

Workflow 是把一个任务拆成**固定的几步**，让 AI 按顺序执行。和 Skill 的区别在于：

| | Skill | Workflow |
|---|---|---|
| 谁决定下一步 | AI 自己判断 | 提前画好流程图，按节点走 |
| 灵活性 | 高（AI 自由发挥） | 低（固定路径） |
| 适合场景 | 开放对话、需要判断的任务 | 流程固定、重复性高的任务 |
| 可控性 | 一般 | 强，每一步输入输出都可见 |

一句话区分：
- **Skill** = 给 AI 一个工具箱，让它自己挑工具
- **Workflow** = 给 AI 一张流水线图纸，第一步干嘛第二步干嘛写死

### 为什么需要 Workflow

纯靠 AI 自由发挥（Agent 模式）虽然灵活，但在一些**流程固定、结果要求稳定**的场景里容易翻车：
- 多走一步、少走一步
- 顺序搞反
- 不同人用效果不一样

Workflow 把流程固化下来，结果就稳定了。

### 实战：一键换衣

这一节是用 Workflow 做了一个"一键换衣"的图像应用。典型的 Workflow 节点大概是：

1. **开始节点**：接收用户上传的照片和想换的衣服描述
2. **图像理解节点**：让多模态模型识别照片里的人物姿势、背景
3. **提示词组装节点**：把识别结果和衣服描述拼成一段完整的图像生成 prompt
4. **图像生成节点**：调用文生图模型出图
5. **结束节点**：返回结果

整个过程用户只需要上传照片 + 说一句"换成黑色西装"，后面四步全自动。

## 三、今天的收获

1. **Skill 和 Workflow 不是二选一，是搭配用的**：复杂应用里，Workflow 管大流程，Skill 管流程里的某一步具体能力
2. **描述写得好 = 成功一半**：不管是 Skill 的 description 还是 Workflow 里的 prompt，本质都是在跟 AI"讲清楚要干嘛"
3. **先跑通再优化**：不管是做 Skill 还是 Workflow，第一步永远是"让它能跑起来"，再回头调参数、改 prompt
