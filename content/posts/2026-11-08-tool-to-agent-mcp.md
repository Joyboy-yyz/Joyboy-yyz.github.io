## 17 · Tool 工具

- **定义**：大模型可以调用的外部能力或函数。模型本身只会输出文本，工具让它能"动手做事"。
- **常见工具**：
  - 计算器：做数学题
  - 搜索引擎：查实时信息
  - 数据库查询：查企业内部数据
  - API 调用：发邮件、订机票、控制智能家居
  - 代码解释器：跑代码、画图、做数据分析
- **为什么需要工具**：
  - 模型知识有截止日期，搜不到今天的新闻
  - 模型算数不行，4321×1234 经常算错
  - 模型不能直接操作电脑、发消息、控制软件
- **一句话**：工具就是大模型的"手和脚"。

## 18 · Tool Calling 工具调用

- **定义**：大模型根据用户意图，自动判断该调用哪个工具、传什么参数，拿到结果后继续回答。
- **完整流程**：
  1. 用户提问："北京今天天气怎么样？"
  2. 模型判断：需要查天气，调用 `get_weather(city="北京")`
  3. 系统执行这个函数，拿到结果："晴，12°C"
  4. 把结果喂回给模型
  5. 模型生成最终回答："北京今天晴，气温 12°C，适合出门。"
- **关键点**：
  - 模型不直接执行工具，它只"决定"调用什么、传什么参数
  - 真正执行工具的是外层程序（Python/JS 后端）
  - 调用结果再回到模型手里，模型才能继续说人话
- **和普通对话的区别**：普通对话模型张嘴就来；Tool Calling 是模型先"查表"再回答。

## 19 · Agent 智能体

- **定义**：以大模型为大脑，能**自主规划、调用工具、观察环境、循环执行**直到完成任务的系统。
- **核心循环（ReAct 模式）**：
  ```
  用户目标
    → 思考（Thought）：下一步该干什么？
    → 行动（Action）：调用某个工具
    → 观察（Observation）：工具返回了什么？
    → 再思考……
    → 直到任务完成，给出最终答案
  ```
- **Agent 的四大要素**：
  - **大脑**：大模型（LLM）
  - **工具**：能调用的外部能力
  - **记忆**：短期（上下文窗口）+ 长期（数据库/RAG）
  - **规划**：把大任务拆成小步骤，一步步执行
- **和普通 Chatbot 的区别**：
  - Chatbot：你问一句，它答一句
  - Agent：你给个目标，它自己拆步骤、调工具、看结果、再调整，直到做完
- **典型例子**：你说"帮我订一张明天去上海的机票"，Agent 会自己查日期、查航班、比价、填乘客信息、确认支付——全程不用你一步步指挥。

## 20 · MCP（Model Context Protocol）

- **全称**：Model Context Protocol，模型上下文协议。
- **谁出的**：Anthropic（Claude 那家公司）推出的开放标准。
- **解决什么问题**：
  - 以前每个 AI 应用要连一个新工具/新数据源，都得单独写一套集成代码
  - 接 Notion 写一套，接 GitHub 写一套，接 Slack 再写一套——重复劳动
  - MCP 定义了一套统一的"插座标准"，工具方按 MCP 写一次，所有支持 MCP 的 AI 应用都能用
- **类比**：MCP 就是"AI 应用的 USB-C 接口"——以前每种设备一个充电口，现在统一一个口，插啥都能用。
- **生态**：VS Code、Claude Desktop、各种 AI IDE 都已经支持 MCP，GitHub、Notion、数据库、文件系统都有现成的 MCP Server。
- **一句话**：MCP 让大模型接外部世界从"一对一接线"变成"即插即用"。

---

## 今日小结

从 Tool → Tool Calling → Agent → MCP，是一条"大模型能力外扩"的线：

- **Tool**：给大模型装上工具（手脚）
- **Tool Calling**：让大模型学会什么时候用、怎么用这些工具
- **Agent**：把模型 + 工具 + 记忆 + 规划串起来，变成能自己干活的智能体
- **MCP**：给所有工具定一个统一接口，不用每次重新接线

理解了这条线，就理解了为什么现在 AI 能从"聊天机器人"进化成"能帮你干活的助手"——从只会说，到会动手。
